Introduction to OOP

Lesson 01 · Paradigm, classes vs objects, why object orientation

What is Object Oriented Programming?

Object-oriented programming (OOP) is a paradigm — a way of thinking about and structuring programs. It is based on the concept of wrapping pieces of data, and behavior related to that data, into special bundles called objects. Objects are constructed from a set of “blueprints”, defined by a programmer, called classes. Instead of thinking about a program as a sequence of instructions, an OO developer thinks about it as a collection of collaborating objects.

The fundamentals of object orientation view a program as a collection of objects that pass messages to each other. Each object decides for itself what to do with a received message. In fact, it is more meaningful to talk about an object-oriented system than a program — an object-oriented system is a set of interacting objects organized into classes. Crucially, the focus is on data and not on function: the definition of data, its attributes and how it will be manipulated is the primary concern, while the exact mechanism of manipulation (procedure or algorithm) is not.

One class (the blueprint) → many objects (instances), each with its own data.

Why object orientation?

Object orientation exists to keep large software projects manageable by human programmers. The lecture highlights four specific benefits, and each one is a favourite theory question:

Modularity
The source code for an object can be written and maintained independently of the source code for other objects. Once created, an object can be easily passed around inside the system.
Information-hiding
By interacting only with an object's methods, the details of its internal implementation remain hidden from the outside world.
Code re-use
If an object already exists (perhaps written by another developer), you can use it in your program. Specialists implement/test/debug complex, task-specific objects you can trust.
Pluggability & debugging ease
If an object is problematic, simply remove it and plug in a replacement — like replacing a broken bolt, not the entire machine.

Procedural vs Object-Oriented: the bank scenario

The lecture uses one real-world requirement to contrast both approaches: “…customers are allowed to have different types of bank accounts, deposit money, withdraw money and transfer money between accounts.”

In the procedural approach, the focus is on procedures, and data lives in shared structures with no protection:

ProceduralApproach.cC-style
bool MakeDeposit(int accountNum, float amount);
float Withdraw(int accountNum, float amount);

struct Account {
    char *name;
    int accountNum;
    float balance;
    char accountType;
};

The problems: focus is on procedures; all data is shared (no protection); it is more difficult to modify; and it is hard to manage complexity. In the object-oriented approach, data and the operations that belong to it are grouped together — an Account class owns its balance and exposes deposit(), withdraw() and transfer() methods. Objects in the problem domain are mapped directly to objects in software, which is why OO modelling feels natural.

Objects as instances of classes

The world conceptually consists of objects, and many objects are of the same type or class. My bank account, your bank account and Bill Gates’ bank account are all different objects, but they share the type BankAccount. We call the object type a class. An object is instantiated from a class using the new keyword:

InstantiationDemo.javaJava
BankAccount myAccount;               // declaration
myAccount = new BankAccount();      // instantiation + initialization

BankAccount gatesAccount = new BankAccount();   // both in one statement

Three definitions you must be able to write precisely:

  • Object — an instance of a class.
  • Instance — a specific realization of any object; each realized variation of an object is an instance.
  • Instantiation — the creation of a real instance (a realized object) from a class.

How to start designing objects

Think about the real world and be natural. First identify objects. Then, for each object, ask two questions: what possible states can this object be in? (its fields) and what possible behavior can this object perform? (its methods). The advantages of OOP follow from this modelling mindset: ease of modeling the real world in a software context, the ability to upgrade systems from small to large scale, easy partitioning of project work based on objects, and reduced maintenance and development costs.

02

Classes & Objects

Lesson 02 (Part 1) · Declarations, fields, methods, access modifiers, constructors

The six OOP concepts

Object-oriented programming simplifies software development and maintenance by providing six core concepts: Object, Class, Inheritance, Polymorphism, Abstraction and Encapsulation. Topics 1–3 cover objects and classes; topics 4–7 cover the remaining four — often called the four pillars of OOP. Keep this list in mind: many exam questions ask you to name or define all six.

Life cycle of an object

  1. Before an object can be created from a class, the class must be loaded.
  2. An object is created from a class when you use the new keyword.
  3. The object lives its life, providing access to its public methods and fields to whoever needs them.
  4. When it’s time for the object to die, it is removed from memory, and Java drops its internal reference to it.

Declaring a class

All classes must be defined by a class declaration — lines of code that provide the name for the class and the body of the class:

Basic formJava
class ClassName
{
    // class body
}
Extended formJava
package mypackage;                      // package declaration
import java.util.*;                     // import statements

[access modifier] class ClassName extends [SuperClass] implements [Interface1, Interface2]
{
    Fields            // variables
    Initializers      // static and instance initializer blocks
    Constructors      // initialize objects
    Methods           // behavior
    other Classes and Interfaces   // nested / inner types
}

The five kinds of members in a class body: fields (variable declarations), initializers (stand-alone blocks run once when the class/object is initialized), constructors (run to initialize an object at creation), methods (declare the class’s behavior) and nested classes / interfaces.

Class naming & saving rules Begin class names with a capital letter (e.g. Student, TennisBall), prefer nouns, and avoid Java keywords, API class names and reserved words. A public class must live in a source file with the same name (Student → Student.java), and you can’t place two or more public classes in the same file.

Fields and methods

A field is a variable defined in the body of a class, outside any of the class’s methods. Fields (also called class variables or instance variables) are available to all methods of the class. A method is a collection of statements grouped together to perform an operation — and a method only runs when it is called.

Employee.javaJava
public class Employee
{
    int id;              // field / data member / instance variable
    String name;         // field

    void display()       // method
    {
        System.out.println(id + " " + name);
    }
}

Creating objects: declaration, instantiation, initialization

Creating an object has three parts: declaration (a variable name is associated with an object type), instantiation (the new operator creates the object in memory and returns a reference to it), and initialization (the new operator is followed by a call to a constructor, which initializes the new object).

CreateObjects.javaJava
public class Employee
{
    int id;
    String name;

    public static void main(String args[])
    {
        Employee e;                     // 1. declaration
        e = new Employee();             // 2. instantiation + 3. initialization

        Employee emp = new Employee();  // all three in one statement

        System.out.println(emp.id);     // accessing member through reference variable
        System.out.println(emp.name);
    }
}
Output
0
null

Default values: numeric fields default to 0 and object fields (like String) default to null.

Objects can be created within the same class (as above) or from a separate driver class — a class that contains main and uses other classes:

TestEmployee.java (driver class)Java
public class NewEmployee
{
    int id;
    String name;
}

public class TestEmployee        // driver class, saved as TestEmployee.java
{                               // (only ONE public class per file in practice)
    public static void main(String args[])
    {
        NewEmployee emp = new NewEmployee();
        System.out.println(emp.id);
        System.out.println(emp.name);
    }
}

3. By constructor

A constructor is a block of code similar to a method that is called when a new instance of an object is created — in fact, it’s the new keyword that calls the constructor. After the object is created, you can’t call the constructor again. It is a special method used to initialize the object.

Constructor rules — memorize 1. The constructor name must be the same as its class name.  2. It must have no explicit return type (they implicitly return an object of their class).  3. Every time an object is created with new, at least one constructor is called.  4. If you don’t write any constructor, the Java compiler creates a default constructor for you.  5. Two types: default (no-arg) and parameterized.
DefaultConstructor.javaJava
public class Employee
{
    private String name;
    private int age;
    private char gender;

    Employee()      // default (no-arg) constructor
    {
        System.out.println("Default constructor executed...");
        System.out.println("Name : " + name + ", Age : " + age + ", Gender : " + gender);
    }
}
ParameterizedConstructor.javaJava
public class Employee
{
    private String name;
    private int age;
    private char gender;

    Employee(String n, int a, char g)      // parameterized constructor
    {
        name = n;
        age = a;
        gender = g;
        System.out.println("Parameterized constructor executed...");
        System.out.println("Name : " + name + ", Age : " + age + ", Gender : " + gender);
    }
}

The default constructor initializes all instance variables to zero or null, while a parameterized constructor accepts values through parameters and assigns them to the fields. Constructor overloading (multiple constructors with different parameter lists) is a common exam question.

this, static & Memory

Lesson 02 (Part 2) · this, constructor chaining, anonymous objects, GC, static members

The this keyword

Recall the Account trap from Topic 2: a = a; did nothing because the parameters shadowed the fields. The solution is the this reference — every object has a reference to itself, represented by the keyword this:

The fixJava
public void setData(int a, int b)
{
    this.a = a;      // this.a = the instance variable; a = the parameter
    this.b = b;
}

At compilation, this is effectively replaced by the current object reference (e.g. myAccount), so the left-hand side becomes the instance variable and the right-hand side the local variable. You can use this in the body of a class constructor or method to refer to the current object — the instance for which the constructor or method has been called.

this() — constructor chaining

Rules for calling constructors with this You can call another constructor only in the very first statement of a constructor using this(...). Each constructor can call only one other constructor — but you can chain constructors. You can’t create loops in which constructors call one another.
ConstructorChaining.javaJava
public class Student
{
    String name;
    int id;

    Student()                       // default constructor
    {
        this("Unknown", 0);         // chained call — MUST be first statement
        System.out.println("Default constructor done");
    }

    Student(String n, int i)        // parameterized constructor
    {
        name = n;
        id = i;
        System.out.println("Parameterized constructor done");
    }

    public static void main(String[] args)
    {
        Student s = new Student();  // runs parameterized first, then default's body
    }
}
Output
Parameterized constructor done
Default constructor done

Constructor chaining refers to the ability to call a constructor inside another constructor — within the same class using this(), or to a superclass constructor using super() (covered in Topic 4). Other uses of this: calling current class methods, passing the current object as an argument, and returning the current object. Also note System.out.println(this); prints the object’s class name and hash code.

Initializer blocks

An initializer block is a lonely block of code placed outside any method, constructor or other block. Initializers are executed whenever an instance is created, regardless of which constructor is used. If a class has more than one initializer, they run in the order they appear, and they are executed before any class constructor:

InitializerTest.javaJava
public class InitializerTest
{
    {
        System.out.println("Initializer block executed...!!!");
    }

    InitializerTest()
    {
        System.out.println("Constructor executed");
    }

    public static void main(String[] args)
    {
        new InitializerTest();
    }
}
Output
Initializer block executed...!!!
Constructor executed

Anonymous objects

Anonymous simply means nameless. An object with no reference is an anonymous object. It can be used at the time of object creation only, and it’s a good approach when you need an object just once:

AnonymousObject.javaJava
Calculation c = new Calculation();   // named reference
c.fact(5);

new Calculation().fact(5);           // anonymous object — no reference stored

How can an object become unreferenced (and hence eligible for garbage collection)? Three ways:

  • By nulling the reference — Employee e = new Employee(); e = null;
  • By assigning a reference to another — e1 = e2; now the first object is unreferenced
  • By an anonymous object — new Employee();

Garbage collection

In Java, garbage means unreferenced objects. Garbage collection (GC) is the process of reclaiming runtime unused memory automatically — a way to destroy unused objects. The Java runtime environment deletes objects when it determines they are no longer being used. It is performed automatically by the garbage collector (a part of the JVM), so Java provides better memory management. Advantages: it makes Java memory efficient because the GC removes unreferenced objects from heap memory, and it needs no extra effort from the programmer.

Working with statics

static describes a field or method that is not associated with a particular instance of a class — static members are associated with the class itself. You don’t need to create an instance to access them; you use the class name, not an object reference.

Static field
Declared with static (e.g. private static int age;). Created and initialized when the class is first loaded. Fields can be static — local variables cannot.
Static method
Associated with the class, not an object. Best-known example: main — called by the JVM to start an application. Java programs run in a static context by default.
Static initializer
A block starting with static { ... } used to initialize static fields. Runs once, when the class is first loaded, before any constructor.
Common uses
Constants, counting instances, serial numbers per object, alternative ways to create instances, and utility functions that need no object at all (like Math).
Static vs instance — who can call what? You can’t access a non-static (instance) method or field from a static method — the static method has no instance to refer to. But you can access static methods and fields from an instance method. Also: you can’t use static on a local variable inside a method — the code won’t compile.
CountingInstances.javaJava
public class InstanceCounter
{
    private static int count = 0;          // shared by ALL instances

    InstanceCounter()
    {
        count++;                           // one more object created
    }

    public static void main(String[] args)
    {
        new InstanceCounter();
        new InstanceCounter();
        new InstanceCounter();
        System.out.println("Instances created: " + count);
    }
}
Output
Instances created: 3

The static counter is shared — but note it only counts instances created during a single run of the program (it resets to zero each execution).

Preventing a class from being instantiated

To create a class instance you need at least one public constructor — and if you don’t provide any constructor, Java inserts a public default constructor. So to prevent instantiation, provide a single private constructor:

MyClass.javaJava
public class MyClass
{
    private MyClass() {}     // prevents instances
    // static methods and fields go here
}

The classic example is Java’s Math class — you never write new Math(); you just call Math.sqrt(2). This idea is also the heart of the Singleton design pattern (one instance only, accessed statically).

Order of initialization (homework answer) 1. If there is a superclass, initialize it first.  2. Static variable declarations and static initializers, in the order they appear in the file.  3. Instance variable declarations and instance initializers, in the order they appear.  4. The constructor.

Inheritance

Lesson 03 (Part 1) · extends, super, overriding vs hiding, final, casting, instanceof

What is inheritance?

Inheritance is when one object (the subclass) acquires all the properties and behaviors of another object (the superclass). It lets you create classes that are derived from other classes. A class that is derived from another is called a subclass (also derived class, extended class, child class); the class from which it is derived is the superclass (also base class, parent class).

  • A derived class automatically takes on all the behavior and attributes of its base class — fields, methods, and nested classes are inherited.
  • A derived class can add features (its own methods and fields) and can also change behavior provided by the base class (overriding).
  • Inheritance is best used to implement is-a relationships — a Car is a Vehicle. This is why inheritance is sometimes referred to as specialization.

The direct superclass is the class the subclass explicitly extends; an indirect superclass is any class above it in the hierarchy. The Java class hierarchy begins with class Object (in java.lang) — every class in Java directly or indirectly extends Object. Java supports only single inheritance of classes: each class has exactly one direct superclass.

Overriding instance methods

An instance method in a subclass with the same signature (name, plus the number and type of its parameters) and return type as an instance method in the superclass overrides the superclass’s method. Always use the @Override annotation so the compiler catches mistakes. Two special rules:

  • Return type — an overriding method may return a covariant return type (a subclass of the original return type).
  • Access modifier — the overriding method can allow more, but not less, access than the overridden method. A protected superclass method can be made public in the subclass (✓) but not private (✗).

Polymorphism

Lesson 03 (Part 2) · Method overloading, overriding, dynamic & static binding

What is polymorphism?

Poly-morphism means the ability to have multiple forms (shapes) of the same thing. In Java, polymorphism is the capability of an action or method to do different things based on the object it is acting upon. Inheritance supplies the machinery (subclass objects can stand in for superclass references), and polymorphism supplies the payoff — the same method call produces different behavior depending on the actual object.

The two faces of Java polymorphism and the binding that resolves each.

Method overloading (compile-time / static polymorphism)

Method overloading is creating multiple methods with the same name within the same class, as long as they have different parameter lists. It lets one method name serve many contexts, making code more concise and readable — the same idea as constructor overloading. There are exactly three ways to overload:

1. Different number of arguments
sum(int a, int b)
sum(int a, int b, int c)
2. Different data types
sum(int a, int b)
sum(double a, double b)
3. Different sequence of types
sum(double a, int b)
sum(int a, double b)
NOT by return type
Changing only the return type does not overload a method — it causes ambiguity and won’t compile.
Overloading.javaJava
class Calculation
{
    void sum(int a, int b)                        // 2 ints
    {
        System.out.println(a + b);
    }
    void sum(int a, int b, int c)                 // different number of arguments
    {
        System.out.println(a + b + c);
    }
    void sum(double a, double b)                  // different data types
    {
        System.out.println(a + b);
    }
    void sum(double a, int b) { }                 // different sequence
    void sum(int a, double b) { }

    public static void main(String args[])
    {
        Calculation obj = new Calculation();
        obj.sum(10, 10, 10);      // picks sum(int,int,int)   -> 30
        obj.sum(20, 20);          // picks sum(int,int)       -> 40
        obj.sum(10.5, 10.5);      // picks sum(double,double) -> 21.0
    }
}
Output
30
40
21.0

Which overload runs is decided at compile time from the number and types of the arguments — that is why it is called static or early-bound polymorphism. (Homework thread: type promotion — when no exact match exists, Java promotes smaller types, e.g. int → long → double, to find a compatible overload.)

An instance method in a subclass with the same signature and return type as a superclass method overrides it. The classic demonstration:

Dynamic binding (late binding)

Because any derived class object can be assigned to a base class variable (Vehicle v = new Car();), Java supports polymorphic behavior: if Car overrides start(), then v.start() calls Car’s version — even though the variable is declared as Vehicle. The type of the object assigned to the variable determines the method that is called.

DynamicBindingDemo.javaJava
// Vehicle.start() prints "Starting ...."
// Car.start()    prints "Car is Starting ...."

Car c = new Car();
c.start();        // Car is Starting ....

Vehicle v = new Car();
v.start();        // Car is Starting ....  <-- Car's version, not Vehicle's!

When the compiler sees v.start(); it knows v is of type Vehicle, but it also knows v could reference any class derived from Vehicle — so the compiler cannot know which version to call. Only when the assignment Vehicle v = new Car(); executes at runtime is the correct version determined. This is dynamic binding / late binding: deciding at run time which method to invoke. In Java, instance methods are dynamically bound — with a few exceptions: private methods, constructors (<init>), super invocations, and final methods.

Static binding (early binding)

Static binding occurs when the compiler can determine the correct version during compile time, before the program runs. All static method calls are resolved at compile time, and — a favourite exam fact — member variables also have static binding, because Java does not support dynamic binding for fields:

FieldBinding.javaJava
// Vehicle declares:  String color = "White";
// Car declares:       String color = "Red";

Car c = new Car();
System.out.println(c.color);     // Red   (c is declared as Car)

Vehicle v = new Car();           // the object is still a Car...
System.out.println(v.color);     // White <-- but fields bind to the REFERENCE type!

The value of a member variable is determined at compile time based on the reference type, not the object type. Methods: object type decides. Fields: reference type decides. This asymmetry is exactly the “hiding fields” idea from Topic 4.

Abstraction

Lesson 03 (Part 3) · Abstract methods, abstract classes, hands-on

What is abstraction?

“We (humans) have developed an exceptionally powerful technique for dealing with complexity: we abstract from it. Unable to master the entirety of a complex object, we choose to ignore its inessential details, dealing instead with the generalized, idealized model of the object.” (Wulf)

Abstraction means extracting only the necessary details. A class represents a real-world entity, and it should contain only the essential details matching the problem domain — think of how a non-medical person models a Cat (cute, has fur, meows) versus how a veterinary surgeon models one (organs, blood pressure, anatomy). Same animal, different level of abstraction.

In Java, abstraction is a mechanism that reduces the complexity of a system by hiding its implementation details from the user. The user only sees what is necessary to perform a task. Everyday example: when you send an SMS you just type text and press send — you don’t know the internal processing of message delivery. That’s abstraction at work.

How is abstraction achieved in Java? Through abstract classes (0–100% abstraction) and interfaces (100% abstraction — Topic 8).

Abstract methods

An abstract method is declared with the abstract keyword and has no implementation (no body) — it ends with a semicolon:

Abstract methodJava
abstract void printStatus();     // no body, no { } — just a signature

Abstract classes

An abstract class is declared with the abstract keyword (placed before class). Its defining properties:

  • Cannot be instantiated — you can never write new Bike() for an abstract Bike.
  • Can be extended by other classes — that is its whole purpose.
  • Can contain both abstract and concrete (implemented) methods.
  • Abstract methods must be overridden by any concrete (non-abstract) subclass.
  • All other class functionality still exists — its fields, methods and constructors are accessed in the same manner as usual (yes, abstract classes CAN have constructors — a beloved exam question).
TestAbstraction.javaJava
public abstract class Bike

    }

    abstract void run();                    // abstract method — no body

    void changeGear()                       // concrete method — has a body
    {
        System.out.println("gear changed");
    }
}

public class Honda extends Bike
{
    void run()                              // MUST implement run()
    {
        System.out.println("running safely..");
    }

Encapsulation

Lesson 03 (Part 4) · Data hiding, accessors & mutators, abstraction vs encapsulation

What is encapsulation?

Encapsulation is the process of wrapping code and data together into a single unit. The lecture’s analogy: a capsule — a single pill that mixes several medicines inside one shell. In Java, the unit is the class: fields (data) and the methods (code) that operate on them live together, and the outside world interacts only through the class’s public face.

Technically, encapsulation is achieved by making the fields private and providing access via public methods. If a field is private, it cannot be accessed by anyone outside the class — the fields are hidden within the class. For this reason, encapsulation is also referred to as data (information) hiding.

Accessor vs mutator — know the names The get methods that allow a field to be viewed are called accessor methods. The set methods that allow a field to be changed are called mutator methods.
MyEncapsulator.javaJava
public class MyEncapsulator
{
    // private member — accessible only within the class
    private String name;

    // public setter (mutator) method to set the value
    public void setName(String name)
    {
        this.name = name;
    }

    // public getter (accessor) method to get the value
    public String getName()
    {
        return name;
    }
}

The SalesPerson example — encapsulation with validation

This is the lecture’s flagship example. Every field is private, and the class keeps total control over what is stored — note how setCommissionRate rejects values outside 0.0–0.20:

SalesPerson.javaJava
public class SalesPerson
{
    private String name;
    private int id;
    private float commissionRate;
    private double sales;

    SalesPerson(String name, int id, double commissionRate)
    {
        setName(name);                       // reuse the mutators
        this.id = id;                        // id has no setter -> read-only field
        setCommissionRate(commissionRate);   // validated!
    }

    public void setName(String n)      { name = n; }
    public String getName()            { return name; }
    public int getId()                 { return id; }        // accessor only

    public void setCommissionRate(double newRate)
    {
        if (newRate >= 0.0 && newRate <= 0.20)
        {
            commissionRate = (float) newRate;
        }
        else
        {
            System.out.println("Rate must be between 0 and 20%");
        }
    }

    public double getCommissionRate()  { return commissionRate; }

    public void addToSales(double s)   { sales += s; }

    public double computeCommission()
    {
        double commission = 0.0;
        if (sales > 0.0)
        {
            commission = sales * commissionRate;
        }
        sales = 0.0;                          // start over
        return commission;
    }
}

Advantages of encapsulation

  • Read-only or write-only classes — provide only a getter (read-only) or only a setter (write-only). id above is read-only.
  • Control over the data — e.g. if id must be greater than 100, write that logic inside the setter. The class has total control over what is stored in its fields (like commissionRate being forced into 0.0–0.20).
  • Hidden storage details — users of a class don’t know (and don’t need to know) how the class stores its data. The class may even change a field’s data type and users won’t have to change any of their code.

Abstraction vs encapsulation

These two are constantly confused — the lecture dedicates a full comparison. The mobile phone analogy: the complex logic in the circuit board is encapsulated in the touch screen (you can’t touch the internals), while the simple user interface provided to you abstracts the phone’s capabilities (you just tap “call”).

Interfaces are contracts

There are situations in software engineering where disparate groups of programmers must agree to a “contract” that spells out how their software interacts — each group writing its code without any knowledge of how the other group’s code is written. Interfaces are such contracts.

An interface is a reference type, similar to a class, that can contain only constants and method signatures (plus, since Java 8, default and static methods with bodies, and nested types). Key facts:

  • A class implements an interface by providing code for each method the interface declares.
  • A class can extend only one other class, but can implement as many interfaces as you need — this is how Java escapes the multiple-inheritance ban.
  • Interfaces cannot be instantiated — only implemented by classes or extended by other interfaces.
  • An interface can’t be used as a base class (a class never extends an interface).

Strict rules (exam gold)

Methods are implicitly public abstract
void bounce();, public void bounce();, abstract public void bounce(); — all five combinations are legal and identical.
Forbidden method modifiers
final (final + abstract never mix), private, protected, and static (without a body) — all fail to compile. Only default and static methods may have bodies.
Fields are implicitly public static final
All fields in an interface are constants. Any combination of modifiers (or none) compiles — you always get public static final.
Interface cannot be private/protected
Top-level interfaces can’t be declared private, protected or transient.
Extends — never implements
An interface can extend one or more other interfaces, but cannot implement anything, and cannot extend a class.
Implement everything or be abstract
A class that doesn’t implement all interface methods must itself be declared abstract.

Exception Handling

Lesson 05 · try/catch/finally, checked vs unchecked, throw vs throws, custom exceptions

What is an exception?

A program can fail for many reasons: some are coding mistakes (which the programmer or the language can handle), others are completely beyond your control (which must be dealt with but not handled). Early languages handled failure rudely — abruptly terminating and printing a dump of the computer’s memory in hexadecimal. Java instead creates special exception objects when an error occurs. As the lecture puts it, an exception is Java’s way of saying: “I give up. I don’t know what to do right now. You deal with it.” When you write a method, you can either deal with the exception or make it the calling code’s problem.

Formally, an exception (short for “exceptional event”) is an event that occurs during the execution of a program and disrupts the normal flow of the program’s instructions. When it occurs, processing gets terminated and a system-generated error message appears — the good thing is that exceptions can be handled. Common reasons: opening a non-existing file, network connection problems, operands out of prescribed ranges, a missing class file, or invalid user input.

Types of exceptions

Checked exceptions
Can be predicted by the programmer. The compiler checks at compile time whether they are handled (catch-or-throw). Example: FileNotFoundException when opening a file.
Unchecked exceptions
Also called runtime exceptions; include programming bugs (logic errors, improper API use). The compiler does not check them. Example: ArithmeticException — division by zero.
Errors
Not exceptions at all. Problems beyond the control of programmer or user (memory, hardware, JVM errors). Typically ignored in code because you can rarely do anything about them.

Exception handling is the mechanism that handles runtime errors (ClassNotFound, IO, SQL, Remote…) and ensures the program’s flow doesn’t break when an exception occurs.

The finally block executes important code such as closing a connection or stream, and it is always executed whether the exception is handled or not. A finally block must follow a try or catch block; each try may have zero or more catch blocks but only one finally:

A stream is simply a flow of characters to and from a program. The other end of the stream can be anything that accepts or generates characters: a console window, a printer, a file on a disk drive, or even another program. Streams have no idea of the structure or meaning of your data — a stream is just a sequence of characters/bonles that your code interprets.

        out.close();                 // ...and close
    }
}

Database Connectivity (JDBC)

Lesson 07 · JDBC architecture, driver types, the 5 steps, ResultSet, MySQL example

What is an API?

API stands for Application Programming Interface. The Java SE APIs define the core Java platform for general-purpose computing, organized in modules whose names start with java. An API is also the document that describes all the features of a product — it represents the classes and interfaces that software programs follow to communicate with each other, and can be created for applications, libraries, operating systems, and so on.

Scale of the Java API The Java language has only about 50 keywords, but the Java API has several thousand classes with tens of thousands of methods. The real challenge of mastering Java isn’t the language — it’s mastering the API. The class library is as much a part of Java as the language itself.

JDBC introduction & why not ODBC

JDBC = Java Database Connectivity, a standard Java API for database-independent connectivity between Java and a wide range of databases. JDBC is used to connect and execute queries with a database; the JDBC API uses JDBC drivers to make the connection. It lets you: establish a connection with a database, send SQL commands, and process the results.

Before JDBC there was ODBC (Open Database Connectivity) — but the ODBC driver is written in C, making it platform dependent and unsecured. Java therefore defined its own API (JDBC) with drivers written in Java.

JDBC architecture

JDBC architecture consists of two layers: the JDBC API (connecting the Java application to the DriverManager) and the JDBC Driver API (connecting the DriverManager to the database drivers). The DriverManager selects the correct driver for the database, establishes the connection, supports multiple drivers simultaneously, and enables connecting to different databases.

Two layers: JDBC API (application ↔ DriverManager) and Driver API (DriverManager ↔ drivers ↔ database).

The four JDBC driver types

TypeDescriptionAdvantageDisadvantage
1. JDBC-ODBC BridgeConverts JDBC calls into ODBC function callsEasy to use; connects to almost any databasePerformance degraded (extra translation); ODBC driver must be installed on the client; now discouraged
2. Native-API (partially Java)Uses the client-side libraries of the database; converts JDBC calls into native callsUpgraded performance vs the bridgeNative + vendor client libraries needed on every client machine
3. Network Protocol (fully Java)Uses middleware (application server) that converts JDBC calls into the vendor-specific protocolNo client-side library; middleware adds auditing, load balancing, loggingNeeds network support; database-specific coding in the middle tier; costly maintenance
4. Thin Driver (fully Java)Converts JDBC calls directly into the vendor-specific database protocolBest performance of all; no software needed on client or serverDriver depends on the database

MySQL Connector/J — the driver used in the practicals — is a Type 4 driver: a pure-Java implementation of the MySQL protocol that requires no native MySQL client libraries.

The 5 basic steps to use a database in Java

Step 1 — Register the driver
Class.forName("com.mysql.cj.jdbc.Driver"); loads the driver class into memory; loading it automatically registers it with the DriverManager.
Step 2 — Create a connection
Connection con = DriverManager.getConnection(url, user, password); e.g. jdbc:mysql://localhost:3306/testdb
Step 3 — Create a statement
Statement stmt = con.createStatement(); responsible for sending SQL to the database.
Step 4 — Execute queries
execute(), executeUpdate() or executeQuery() run the SQL and return results / row counts.
Step 5 — Close the connection
con.close(); frees resources — it also closes the Statement and ResultSet created from it.

PreparedStatement — safe & fast

Prepared statements are for queries executed multiple times with different values. The SQL is parsed and compiled by the database only once; values are supplied later via ? placeholders. This improves performance and helps prevent SQL injection:

InsertExample.javaJava
String sql = "INSERT INTO emp VALUES (?, ?, ?)";
PreparedStatement ps = con.prepareStatement(sql);

// set values for the placeholders — indices start at 1
ps.setInt(1, 101);
ps.setString(2, "John");
ps.setDouble(3, 5000.0);

ps.executeUpdate();

ResultSet — processing query data

A ResultSet holds the data returned by a query. Rows are retrieved sequentially; a cursor points to the current row and next() moves it forward (it returns false when rows run out). Column values can be fetched by index (indices start at 1, not 0!) or by name (slightly less efficient):

ResultSetDemo.javaJava
ResultSet rs = stmt.executeQuery("SELECT * FROM students");
while (rs.next())                            // move cursor row by row
{
    int id = rs.getInt("id");                // by column name
    String name = rs.getString("name");

    // equivalent, by index (1-based):
    // rs.getString(1);  rs.getInt(2);

    System.out.println(id + " : " + name);
}
rs.close();                                  // always close the ResultSet
