Introduction to DSA

Lecture 1 · Introduction 2026 · Labs 1–2

What is data?

Data is a collection of facts from which conclusions may be drawn — e.g. a temperature reading of 38°C. Data comes in many types: textual (your name), numeric (your ID TG/2025/0001), audio (your voice) and video (voice + picture).

The three core definitions

TermDefinition (memorize wording)
AlgorithmA step-by-step procedure which can be applied to data to achieve some goal
ProgramImplements an algorithm
Data structureThe manner in which data is represented in the computer to facilitate its access and manipulation by an algorithm — the organization of data needed to solve the problem
Exam alert“A data structure is a particular way of storing and organizing data in a computer so that it can be used efficiently and effectively.” It is the logical / mathematical model of the organization of data.

Classifying data structures

CharacteristicOption AOption B
ArrangementLinear — items in a sequence (array)Non-linear — no sequence (tree, graph)
Element typesHomogeneous — all elements same type (array)Non-homogeneous — may differ (struct)
MemoryStatic — size fixed at compile time (array)Dynamic — grows/shrinks at run time (linked list)

The hierarchy splits into primitive data structures (int, float, char, boolean — built into the language) and non-primitive (arrays, lists, stacks, queues, trees, graphs — built from primitives).

The six data structure operations

OperationDescription
TraversingAccessing each data element exactly once so that certain items may be processed
SearchingFinding the location of a data element (key) in the structure
InsertionAdding a new data element to the structure
DeletionRemoving a data element from the structure
SortingArranging data elements in logical order (ascending/descending)
MergingCombining elements from two or more structures into one
Exam alertAll six operations are frequently listed as a 6-mark question. Memorize them in the exact order: Traversing, Searching, Insertion, Deletion, Sorting, Merging.

Abstract Data Type (ADT)

DefinitionAn ADT is a collection of data and a set of operations on that data, defined as a mathematical model of the data objects plus the functions that operate on them — without regard to how they will be implemented.

In other words, an ADT tells you what the data represents, not how it is constructed. The user interacts only with the interface; the implementation is hidden one level deeper, and that hidden implementation is what we call the data structure.

  • Primitive data structures — int, float, boolean, char (e.g. an int stores numerical values with operations +, −, ÷ …). We never worry how an int is implemented in hardware.
  • Abstract data structures — linked list, tree, graph, stack, queue: an implementation-independent view.
  • Data structures represent the objects of the ADT; algorithms manipulate the data structures to implement the ADT's operations.

Why study DSA?

  • Component reuse — once implemented, a data structure can be reused across many applications.
  • Adding structure to data makes algorithms simpler, easier to maintain, and often faster.
  • Design goals: correctness, efficiency, robustness, adaptability, reusability.
  • Uses: real-world data storage, programmer's tools (stacks, queues), real-world modelling (graphs, queues).

Performance analysis

When several algorithms solve the same problem we choose the best using performance analysis: the process of calculating the space and time required by the algorithm.

  • Space complexity — total memory needed: program instructions, constants, variables (plus recursion stack). E.g. return b*b; needs 2 bytes for b + 2 bytes for the return value = a fixed 4 bytes → constant space complexity.
  • Time complexity — computer time to execute. Depends on machine, compiler, algorithm and input; we therefore analyze the number of elementary steps as a function of input size n, and usually report the worst case.
Analysis rulesSimple statement sequence s1; s2; … → O(1). A single loop over n items → O(n). Nested loops (n × n) → O(n²). Even for j…for k<j (triangular) is still O(n²).

Asymptotic notations

Counting steps — a worked example

WORKEDAnalyzing a sum loop
1  i = 1;  sum = 0;        /* 1 unit each  → 2 total     */
2  while (i <= N) {          /* 1 init + (N+1) tests + N incs */
3      sum = sum + 3;      /* 4 units × N executions      */
4  }                          /* … plus loop bookkeeping     */

Total cost = 6N + 4 → the most significant term is N → O(N).

Why 6N + 4?

Lines 1 and 4 cost one unit each (2). Line 2 costs 2N + 2 (initialization, N+1 tests, N increments). Line 3 executes N times × 4 units = 4N. Sum: 2 + 2N + 2 + 4N = 6N + 4. Asymptotically only N matters → O(N).

Worst, average and best case

  • Worst case — longest running time for any input of size n; an upper-bound guarantee. Sorting data that is in reverse order.
  • Best case — e.g. sorting data that is already sorted.
  • Average case — may be difficult to define what “average” means.
  • The worst case can occur fairly often — e.g. searching a database for a missing record.

Stacks

Lecture 2 · Lab 2

What is a stack?

DefinitionA stack is a linear data structure which can be accessed only at one end — the top — for storing and retrieving data. Insertions and deletions are made at the top only, so elements are removed in the reverse order of insertion: Last-In, First-Out (LIFO).

Think of the spring-loaded cafeteria plate dispenser (the origin of the name), a stack of CDs, or a stack of plates: you can only touch the top item. Removing it exposes the next-to-last item, and so on. A stack is a constantly changing object.

The ADT operations

OperationPreconditionPostcondition / behaviour
Push(item)Stack initialized, not fullItem becomes the new top
Pop()Stack initialized, not emptyTop element removed and returned
Peek / Top()Not emptyValue of the top element without removing
IsEmpty()—True if the stack has no elements
IsFull()—True if no more items fit (array version)
MakeEmpty—Removes all elements

Array implementation & the TOP pointer

The stack is built on an array with restricted access plus a variable top holding the index of the top element. TOP is initialized to −1, so an empty stack is detected with top == -1.

Position of TOPStatus of the stack
top = −1Stack is empty
top = 0First element just added
top = N−1Stack is full (size N)
top = NStack overflow!
Exam alertOn push: increment TOP first, then store: top = top + 1; stack[top] = item;  On pop: read first, then decrement: item = stack[top]; top = top - 1;  Always check full-before-push and empty-before-pop.

The algorithms (exam standard)

/* INIT */   INIT_STACK(STACK, TOP):  TOP := -1

/* PUSH */    IF TOP = MAX  → print "Stack is full" (overflow), exit
             otherwise: TOP := TOP + 1;  STACK(TOP) := ITEM

/* POP */     IF TOP = -1  → print "Stack is empty" (underflow), exit
             otherwise: ITEM := STACK(TOP);  TOP := TOP − 1

/* IS_FULL */  IF TOP = MAX  → STATUS := true   else false
/* IS_EMPTY */ IF TOP = -1  → STATUS := true   else false

Where stacks are used

  • Method calls — most microprocessors are stack-based: return address and arguments are pushed on call, popped on return.
  • Reversing — push all letters of a word, pop them out in reverse order.
  • Compilers / expression evaluation — converting infix expressions to prefix/postfix and evaluating them.
  • Browser back button — URLs are pushed as you visit; back pops the current page.
  • Undo in text editors.

Infix, prefix and postfix notation

Infix places the operator between operands (A + B). Prefix (Polish) places it before (+ A B). Postfix (Reverse Polish) places it after (A B +). No parentheses or precedence rules are needed in prefix/postfix — which is why compilers love them.

Stack via linked list

The array stack works only for a fixed number of values — unsuitable when the data size is unknown. A linked-list stack grows without limit: every new element is inserted as the new top, pointed at by top.

void push(int x) {
    node *n = malloc(sizeof(node));
    n->data = x;  n->next = top;   /* new node points at old top */
    top = n;                        /* top now points at new node */
}
int pop() {
    node *tmp = top;  int n = tmp->data;   /* 6 steps: temp, point,   */
    top = top->next;                          /* store, advance, free,   */
    free(tmp);  return n;               /* return                  */
}

Array vs linked list implementations: the array gives best performance but a fixed size; the linked list gives constant-time push/pop and can grow to infinite size, but is slower in the common case.

What is a queue?

DefinitionA queue is a linear data structure similar to a stack, but insertions are made at the rear and deletions at the front. The first element inserted is the first removed: First-In, First-Out (FIFO) — like queuing at the bank or bus stop.

Operations

The linear queue problem → circular queues

In a linear queue, dequeuing only moves front forward. After removing elements, rear may sit at the end of the array while free cells exist at the front — the queue looks “full” but is not! The fix: let indices wrap around — a circular queue (also called a ring buffer).

SituationCondition
Queue is full(rear == SIZE-1 && front == 0) || (front == rear+1)
Wrap rear to startif rear == SIZE-1 && front != 0 then rear = −1 before incrementing
Empty bufferread pointer == write pointer

Perform: Enqueue 5, 4, 7 · Dequeue · Enqueue 8, 9 · Dequeue · Enqueue 1, 2

Indices 0–3.
1. enqueue 5 → [5,·,·,·] · enqueue 4 → [5,4,·,·] · enqueue 7 → [5,4,7,·]
2. dequeue → removes 5 (front now 1) → [·,4,7,·]
3. enqueue 8 → [·,4,7,8] — rear = 3 = SIZE−1; enqueue 9 must wrap: rear → 0 → [9,4,7,8]
4. dequeue → removes 4 (front now 2)
5. enqueue 1 → rear 1: [9,1,7,8] · enqueue 2 → rear is at 2, but 2 holds 7 and front = 2 → next cell would make front == rear+1… position 3 is taken by 8, wrap to check: the queue is full (4 elements: 7, 8, 9, 1) → enqueue 2 fails with overflow.

Final: [9, 1, 7, 8] with front = 2, rear = 1 — a perfectly wrapped ring.

Queue variants & applications

  • Variants: normal (FIFO), circular, double-ended queue (deque), priority queue.
  • In the OS: printer spooling (SPOOLING), keyboard buffer (stores keystrokes as you type), CPU job queue in multi-user systems, pipeline.
  • Real world: grocery / bank lines, aeroplanes at airports, data packets in communication.
  • Simulation programs, games, processor scheduling.

Queue via linked list

Same motivation as the stack: unlimited size. Keep a queue struct with count, front, rear; enqueue at the rear, dequeue at the front — no shifting, no wraparound logic.

struct queue { int count; node *front; node *rear; };

void enqueue(queue *q, int value) {
    node *tmp = malloc(sizeof(node));
    tmp->data = value;  tmp->next = NULL;
    if (!isempty(q)) { q->rear->next = tmp; q->rear = tmp; }
    else              { q->front = q->rear = tmp; }   /* first node */
    q->count++;
}
int dequeue(queue *q) {
    node *tmp = q->front;  int n = q->front->data;
    q->front = q->front->next;  q->count--;
    free(tmp);  return n;
}
Clever factA circular linked list can implement a queue with only one pointer: keep a pointer to the last node — the front is always last->next.

Linked Lists

Lecture 4 · Lecture 5 · Labs 4–5

From lists to linked lists

A list is a finite sequence of elements (e.g. a list of integers or records). It can be stored two ways:

StorageDescriptionWeakness
Contiguous (array)Elements physically adjacent in memoryFixed size, wastes space, front insertion shifts all elements
Non-contiguous (linked list)Elements stored “somewhere” in memory; order kept by explicit linksNo random access → no binary search; extra pointer memory; worse cache locality
Exam alertLinked list advantages over arrays: 1) dynamic size (grows/shrinks at run time), 2) easy insertion/deletion (no shifting). Drawbacks: no random access (must traverse sequentially from the first node — so no binary search), extra space per node for a pointer, and arrays have better cache locality.

Anatomy of a node

12next ●→ 99next ●→ 37NULL
Head points to the first node · each node = data + pointer to next · the last node's next is NULL
struct Node {
    int          data;     /* the payload — any type      */
    struct Node *next;     /* self-referencing pointer    */
};                           /* head: pointer to first node  */

Nodes are created dynamically with malloc(), which requests a block of memory from the heap: struct node *np = (struct node*) malloc(sizeof(struct node));. Because memory comes from anywhere, the address of every node is stored in the previous node — that is why pointers are essential.

Insertion — the three positions

1 · Insert at the beginning (4 steps)

void insert(struct Node **head_ref, int new_data) {
    struct Node *new_node = malloc(sizeof(struct Node));
    new_node->data  = new_data;      /* E->data = data   */
    new_node->next  = (*head_ref);   /* E->next = head   */
    (*head_ref)     = new_node;      /* head   = E      */

    struct Node *last = *head_ref;
    new_node->data = new_data;  new_node->next = NULL;

}

Circular linked lists

DefinitionA circular linked list has no beginning and no end: the last node's next stores the address of the first node. The structure definition is identical to a singly list — only the last link differs (head instead of NULL).
  • Any node can be a starting point — traverse the whole list from anywhere; stop when the first visited node appears again.
  • Queue-friendly: only one pointer is needed (to the last node) — front is always next of last.
  • OS round-robin: running applications are kept in a circular list and cycled through, each getting a CPU time slice — reaching the end wraps to the front automatically.
  • Multiplayer games: players are kept in a circular list; the pointer advances as each turn ends.

Binary Search Trees

Lecture 7 (Trees part 2) · Lab 7

The search-order property

DefinitionA binary search tree (BST) is a binary tree where, for every node: 1) the left subtree contains only keys less than the node's key, 2) the right subtree contains only keys greater than the node's key, and 3) both subtrees are themselves BSTs. Duplicates are not allowed.
Left subtree < node < right subtree, everywhere. Note: BSTs don't have to be symmetrical.

Search — TreeSearch

To search for key k, trace a downward path from the root: each comparison picks the next subtree. Reaching a leaf (NULL) means not found.

Algorithm TreeSearch(k, v)
    if (v == NULL) return v;              /* not found        */
    if (k < key(v))
        return TreeSearch(k, T.left(v));    /* go left          */
    else if (k == key(v))
        return v;                          /* found!           */
    else  /* k > key(v) */
        return TreeSearch(k, T.right(v));   /* go right         */

Insertion

Search for the new key; when the search falls off the tree at (leaf) node w, insert the new key there. Example — insert 63: 63 > 50 → right · 63 < 76 → left · 63 < 65 → left · 63 > 59, and 59 has no right child ⇒ 63 becomes 59's right child.

AVL Trees & Balanced Trees

Self-balancing search trees

Plain BSTs degenerate when data arrives in order. The family of balanced search trees fixes this: AVL trees, 2-3 trees, 2-3-4 trees, B-trees, and Red-Black trees.

DefinitionAn AVL tree is a self-balancing binary search tree. The balance factor (BF) of every node must be −1, 0 or +1:
BF = height(left subtree) − height(right subtree). Every AVL tree is a BST, but not every BST is an AVL tree.
A valid AVL tree — balance factor (red) ∈ {−1, 0, +1} at every node
Exam alertYou will be shown a BST and asked “is this an AVL tree?” — compute BF for every node. One node with BF = ±2 disqualifies it. A right subtree of height 3 vs left of height 1 (BF = −2) means not AVL.

Maintaining balance

  • Inserting a node can raise a tree's height by at most 1; removing can lower it by at most 1.
  • After every insert/delete, walk back up to the root updating heights; if a new balance factor reaches ±2, restore balance with a rotation around that node.
  • Insertion into an AVL tree runs in O(log n); new nodes are always inserted as leaves (BST logic first, then rebalance).

Red-Black trees (introduction)

A Red-Black tree is another BST variant where every node is coloured RED or BLACK. Its rules:

  1. It must be a Binary Search Tree.
  2. The ROOT must be BLACK.
  3. Children of a RED node must be BLACK — no two consecutive red nodes.
  4. Every root-to-leaf path has the same number of BLACK nodes.
  5. Every new node is inserted RED.
  6. Every leaf (NULL node) is BLACK.

After each insertion, check the properties; fix violations with a Recolor, or a Rotation followed by Recolor. Insertion logic: if the parent is BLACK → done. If the parent is RED: check the parent's sibling — if BLACK/NULL, rotate + recolor; if RED, recolor and recheck upward.

What is a heap?

DefinitionA heap is a binary tree ADT with two special properties: 1) Shape — it must be a complete binary tree (all levels full except possibly the last, which is filled strictly left to right); 2) Order — every parent is ≤ all of its children (min-heap) or ≥ all of its children (max-heap).

Important heap facts

  • Duplicates are allowed — no restriction against them.
  • A heap does NOT follow BST rules: the left child does not have to be smaller than the right child.
  • Only the parent-vs-children ordering matters; ordering between siblings is irrelevant.
  • A tree that is complete but violates order is not a heap; a heap-shaped tree that is not complete is not a heap either.

Operations

  • Insertion (growing) — a new node can only be added at the left-most available spot at the lowest level; then bubble it up (swap with parent) if the order property is violated. After inserting 85 under a max-heap, sifting up restores the heap.
  • Deletion (shrinking) — heaps normally remove the root (the largest/smallest value). Move the last node to the root, then sift down.
  • Find max/min — it is always at the root: O(1).

Heapify, Build-Heap, Heap Sort

Heapify(A, i) — assume both subtrees of i are already heaps; pick the largest child, compare with the parent, swap if needed, and recurse: this “sift-down” makes i's subtree a heap.

Heapify(A, i) {
    l = left(i);  r = right(i);
    if (l <= heapsize && A[l] > A[i])  largest = l;   else largest = i;
    if (r <= heapsize && A[r] > A[largest]) largest = r;
    if (largest != i) { swap(A[i], A[largest]); Heapify(A, largest); }
}
BuildHeap(A) {                        /* bottom-up: leaves are already heaps */
    heapsize = length(A);
    for (i = length/2 downto 1) Heapify(A, i);
}
HeapSort(A) {                          /* max-heap → ascending sort */
    BuildHeap(A);
    for (i = length downto 2) {
        swap(A[1], A[i]);               /* biggest element to its final spot */
        heapsize--; Heapify(A, 1);      /* restore heap on the rest          */
    }
}
Exam alertHeap sort's two phases: build a heap from the array, then repeatedly extract the root. To sort ascending → use a MAX-heap; to sort descending → use a MIN-heap. Complexity: O(n log n) in worst, best AND average case; space O(1) because it is not recursive. The Linux kernel uses it for this guaranteed behaviour.

Sorting Algorithms

Lecture 10 (I & II) · Labs 8–9

Why sorting matters

Sorting means arranging data in a particular format (numerical or lexicographical). Its importance: data searching can be optimized to a very high level if the data is stored sorted, and sorted data is more readable.

Bubble sort

Repeatedly step through the list comparing adjacent pairs; swap if out of order. After pass k, the k largest values have “bubbled” to the end. Sorting needs one whole pass without any swap to be recognized as complete.

for (i = 0; i < n-1; i++)
    for (j = 0; j < n-i-1; j++)
        if (arr[j] > arr[j+1]) {        /* swapping condition  */
            temp = arr[j]; arr[j] = arr[j+1]; arr[j+1] = temp;
        }
WORKEDBubble sort (5 1 4 2 8)

Pass 1: (5,1)→swap→1 5 4 2 8 · (5,4)→swap→1 4 5 2 8 · (5,2)→swap→1 4 2 5 8 · (5,8)→ok.
Pass 2: (1,4)ok · (4,2)→swap→1 2 4 5 8 · rest ok.
Pass 3: no swaps — but the algorithm needs this whole clean pass to know it is sorted.
Comparisons for 6 elements worst case: 5+4+3+2+1; for N: N(N+1)/2 ≈ N² → O(n²).

Selection sort

Find the smallest remaining number and exchange it with position 0; repeat for positions 1, 2, … The sorted region grows from the left. Same O(n²) comparisons as bubble sort, but far fewer swaps (at most n−1), so it is faster in practice.

Insertion sort

Maintain a sorted lower part of the array; take the next element (the “hole”), shift larger elements right, and drop it into its place — exactly how you sort playing cards in your hand.

for (k = 1; k < n; k++) {
    temp = arr[k];                 /* value to insert        */
    j = k - 1;
    while (temp < arr[j] && j >= 0) {
        arr[j+1] = arr[j];          /* shift larger value up  */
        j--;
    }
    arr[j+1] = temp;                /* drop into the hole     */
}
Why keep insertion sort?It is O(n²) in the worst case but brilliant on nearly-sorted data (approaching O(n)) — and it is the natural choice for small inputs.

Can we do better than n²?

Selection, insertion and bubble are all proportional to n². Other sorts achieve n log n: merge sort, quick sort, heap sort. Since log n ≪ n, an n log n sort wins massively as n grows — e.g. n = 1,000,000: n² = 10¹² vs n log n ≈ 2×10⁷.

Merge sort — divide & conquer

Merge sort is recursive and needs one extra array in memory. The divide-and-conquer template: 1) Divide the input into two halves (solve directly if tiny); 2) Recur on each half; 3) Conquer — merge the two sorted halves.

void mergesort(int a[], int i, int j) {
    if (i < j) {
        int mid = (i + j) / 2;
        mergesort(a, i, mid);          /* left recursion  */
        mergesort(a, mid+1, j);        /* right recursion */
        merge(a, i, mid, mid+1, j);     /* merge two runs  */
    }
}
/* merge: repeatedly copy the smaller front element of the two
   sorted lists into temp[], then copy back — O(n) per merge */
WORKEDMerge sort (10, 5, 8, 2, 12, 6, 3, 4)

Split: [10 5 8 2 12 6 3 4] → [10 5 8 2] [12 6 3 4] → [10 5][8 2] [12 6][3 4] → [10][5] [8][2] [12][6] [3][4].
Merge: [5 10] · [2 8] · [6 12] · [3 4] → [2 5 8 10] · [3 4 6 12] → [2 3 4 5 6 8 10 12].
Complexity: O(N·log N) — log N levels of splitting, N work merging each level.

Quick sort — partition & recurse

Pick a pivot p; move all values less than p to its left and all values ≥ p to its right; then quicksort each side. It is a comparison sort, in-place (tiny extra memory), and usually the fastest in practice — but not stable (equal elements may reorder).

/* partition a[left..right]: pivot = a[left] */
pivot = a[left];  l = left + 1;  r = right;
while (l < r) {
    while (l < right && a[l] < pivot)  l++;
    while (r > left  && a[r] >= pivot) r--;
    if (l < r) swap(a[l], a[r]);
}
a[left] = a[r];  a[r] = pivot;      /* pivot lands at its final index */

Hashing

Lecture 14 · Hash table & hash function

The problem hashing solves

Searching an unsorted array may require examining every element. If we knew the index of a value in advance, search would take one probe — O(1). The “magic function” that turns a key into an index is the hash function.

DefinitionHashing is the process of mapping a key value to a position in a table. A hash function maps key values to positions; a hash table is the array holding the records. Searching can then be done in O(1) regardless of table size.
  • Hash tables provide near-O(1) insert/locate — significantly faster than trees (O(log₂n)).
  • Similar to arrays — you must know roughly how many items will populate the table (to pick the size).
  • Sequential access makes little sense — items land in scattered (randomized) positions.

The Division-Remainder method

Exam alertArrayIndex = someNumber % arraySize — the classic hash function, called the Division-Remainder method. Any integer mod arraySize lands in the range 0 … arraySize−1, e.g. anything mod 51 yields 0…50; 5280 mod 51 gives a value in that range, period.
WORKEDConverting words to numbers (lecture example)

Translate letters (a=1, b=2, …, t=20, s=19) and add: cats = 3+1+20+19 = 43 → “cats” hashes to location 43.

Many words can also sum to 43 — e.g. other letter combinations with the same total. Different keys mapping to the same location are called synonyms, and the event of two keys wanting the same slot is a collision.

WORKEDDivision method with size 125

42000 % 125 = 0 → index 0 · 42200 % 125 = 75 → index 75 · 42249 % 125 = 124 → index 124. All keys hash inside 0–124 ✓

42000, 42125, 42250, 42375… are all multiples of 125 apart — they ALL hash to index 0. Similarly 40001, 42126, 42151… all hash to 1. A large input range squeezed into a small table guarantees collisions — the price of saving space (we cannot reserve a spot for every possible value).

Hash table anatomy & operations

A hash table is an array of records; each record carries a special field, its key (e.g. a Number field like 506643548). To insert a record: compute the hash value (e.g. Number mod 701) and store the record at that index. For 580625685: 580625685 mod 701 = 3.

  • Insert — compute hash value; if occupied (collision), move forward until an empty spot is found; place the record there.
  • Search — compute hash value; check that slot's key; if it doesn't match, keep moving forward until the key is found or an empty spot is reached (then it's absent).
  • Delete — never leave a plain empty spot! Mark it specially (e.g. “previously occupied”) so future searches keep probing past it instead of stopping early.
Exam alertThis forward-walking scheme is linear probing. The deleted-slot marking rule is a favourite trick question: deleting must NOT create an ordinary empty slot, or searches for keys probed through it would stop too early.
